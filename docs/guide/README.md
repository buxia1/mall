# 项目导读

这套文档是给**你自己**看的，不是 API 手册，也不是交接文档。
目的只有一个：让你能在这个仓库里自己走一圈，就把「整个项目怎么长的、每一处为什么这么写」梳理清楚。

## 这个项目是什么

照 `复现文档` 的规格，从零重建一个精简版 mall 电商系统。

判据只有一条：**功能对得上、接口对得上、能跑通**——内部怎么实现完全由你决定。
两个前端（`mall-admin-web`、`mall-app-web`）不改，它们已经把接口路径、参数名、响应结构写死了，
所以后端是「按前端契约反推规格」实现的。这决定了本项目最重要的一条约束：

> 接口路径、参数名、响应结构、状态码（`200` 成功 / `401` 未登录）**必须对齐**，改了前端就废。

## 和其它文档的关系

- `AGENTS.md` —— 协作规范（范围顺序、Git 规范、CRUD 边界、秒杀约束）。**规则以它为准。**
- `docs/superpowers/specs/` `docs/superpowers/plans/` —— 模块 1、2 动手前的设计与实施计划，历史记录。
- `document/复现文档/`（不在本仓库，在参考项目里）—— 需求来源：数据模型、接口规格、技术决策清单、验收标准。
- `docs/guide/`（本目录）—— **读完代码之后的总结与导航**，讲"为什么"，前两者讲"做什么"。
