## 一、模块分层

```
mall-admin    ← 只有它可执行（有 main、有 application.yml）
  ├── mall-security    ← JWT 与 Spring Security 过滤器/授权扩展
  ├── mall-mbg         ← 持久化：表模型 + Mapper（注解 SQL，没有 XML）
  └── mall-common      ← 与业务无关的基础设施：统一返回/异常/分页/Redis/日志
        ↑ 上面三个都依赖它，它不依赖任何业务
```

依赖方向是单向的，**`mall-common` 不允许反过来依赖业务模块**——否则基础层会被业务污染，
后面想做 `mall-portal` 时就没法复用了。

| 模块 | 文件数 | 职责 | 不允许出现的东西 |
|---|---|---|---|
| `mall-common` | 23 | 返回体、错误码、异常、分页、Redis 封装、请求日志 | 任何具体业务概念（商品、订单、权限） |
| `mall-mbg` | 19 | `Ums*` 模型 + `Ums*Mapper`（MyBatis 注解 SQL） | 业务规则、事务、HTTP |
| `mall-security` | 13 | JWT 签发校验、会话、动态 URL 鉴权、过滤器链 | 具体业务的接口实现 |
| `mall-admin` | 29 | Controller / Service / DTO，后台管理接口 | 直接操作 `RedisTemplate`（要走 `RedisService`） |

> `mall-admin` 只有 29 个文件却承载了 40 多个接口，是因为本项目**不用 XML 写 SQL**：
> 所有增删改查都写在 Mapper 接口的注解里（见 `UmsAdminMapper`），没有 `mapper/*.xml`。

## 三、一次请求的完整链路（最重要的一节）

以 `GET /admin/info` 为例，从浏览器点到 MySQL：

```
mall-admin-web (:5173)
  │  axios baseURL = VITE_BASE_SERVER_URL = http://localhost:8080
  │  header: Authorization: Bearer <jwt>
  ▼
① 跨域预检 OPTIONS
   SecurityConfig.corsConfigurationSource()   ← 放行 http://localhost:*
   CorsFilter 排在鉴权之前，预检直接被应答，不会进鉴权逻辑
  ▼
② SecurityFilterChain（SecurityConfig.securityFilterChain）
  ▼
③ JwtAuthenticationFilter                （OncePerRequestFilter，在 UsernamePasswordAuthenticationFilter 之前）
   ├─ 从 Authorization 头剥掉 "Bearer "
   ├─ JwtTokenUtil.getIdentity(token)      验签 + 过期 → AdminIdentity(adminId, username)
   └─ AdminTokenService.isActive(token)    查 Redis 里这个会话还在不在  ← 登出就是删这个键
   通过 → SecurityContextHolder 放入 UsernamePasswordAuthenticationToken(principal = AdminIdentity)
  ▼
④ authorizeHttpRequests
   ├─ /admin/login、/admin/refreshToken → permitAll
   └─ 其余 → DynamicAuthorizationManager（动态 RBAC）
  ▼
⑤ DynamicAuthorizationManager.check
   ├─ 没认证 / principal 不是 AdminIdentity → false → 401
   ├─ 取请求路径（servletPath，去掉 contextPath）
   ├─ 拿该 adminId 的资源 URL 集合：
   │    先读 Redis key mall:security:authorization:resources（存 Map<adminId, Set<url>>）
   │    读不到才查库 UmsAdminMapper.selectResourcesByAdminId 并回填
   └─ AntPathMatcher 逐个匹配，命中任一即放行；全不中 → false → 403
  ▼
⑥ DispatcherServlet → UmsAdminController.info(@AuthenticationPrincipal AdminIdentity)
   @AuthenticationPrincipal 就是取 SecurityContext 里的 principal
  ▼
⑦ UmsAdminService.info(adminId)
   selectById + selectMenusByAdminId + selectRolesByAdminId → AdminInfo(username, menus, icon, roles)
  ▼
⑧ UmsAdminMapper（注解 SQL）→ MySQL mall 库
  ▼
⑨ 返回 CommonResult<AdminInfo> → Jackson 序列化 → 前端
```

**旁路的三件事，出问题时都从这里找**：

| 组件 | 作用 |
|---|---|
| `GlobalExceptionHandler`（`@RestControllerAdvice`） | 业务异常/参数校验/兜底异常 → 统一 JSON |
| `JsonAuthenticationEntryPoint` / `JsonAccessDeniedHandler` | 未认证 → HTTP 401；已认证无权限 → HTTP 403，都是 `CommonResult` |
| `WebLogAspect`（`@Around` 切 controller） | 记录 URL / 入参 / 返回值 / 耗时，跳过 multipart |

### 为什么 401 和 403 要分开

前端 `utils/http.ts` 里硬编码了 `if (res.code === 401)` → 弹"重新登录"。
所以「没登录」必须是 401，「登录了但没这个权限」必须是 403，混了前端行为就不对。
这也是 `DynamicAuthorizationManager` 里先判 `isAuthenticated()` 再判资源的原因。

## 五、我要看 X，该读哪些文件

| 我想搞清楚 | 读这些 |
|---|---|
| 登录怎么发 token | `UmsAdminService.login` → `AdminTokenService.login` → `JwtTokenUtil.generateToken` |
| token 怎么被校验 | `JwtAuthenticationFilter` → `JwtTokenUtil.getIdentity` → `AdminTokenService.isActive` |
| 登出为什么能立刻失效 | `AdminTokenService.logout`（删 Redis 会话键，不是改 JWT） |
| 权限是怎么判的 | `DynamicAuthorizationManager.check`（URL → 资源 → AntPathMatcher） |
| 改了权限为什么不重启就生效 | `AuthorizationCacheEvictor` + `UmsResourceService.create/update/delete` + `UmsRoleService.allocResource` |
| 统一返回体长什么样 | `CommonResult`、`ResultCode` |
| 异常怎么变成统一 JSON | `GlobalExceptionHandler`、`ApiException`、`Asserts` |
| 分页怎么做的 | `CommonPage.restPage` + 各 Service 里的 `PageHelper.startPage(pageNum, pageSize)` |
| Redis 怎么用的 | `RedisService`（业务只依赖接口）、`RedisServiceImpl`、`BaseRedisConfig`（序列化） |
| 跨域怎么放开的 | `CorsProperties` + `SecurityConfig.corsConfigurationSource` |
| 401 / 403 怎么输出的 | `JsonAuthenticationEntryPoint` / `JsonAccessDeniedHandler` |
| 请求日志在哪 | `WebLogAspect`、`WebLog`、`RequestUtil` |
| 前端多选 ID 怎么传的 | `IdListParams`（空选时前端传的是空串） |

## 六、几个跨模块的约定（不知道会踩坑）

1. **写接口返回"裸" `CommonResult`，`data` 是影响行数/条数**。原版就这样，前端按这个写的，
   不要"顺手"改成泛型 DTO——JSON 结构必须一致。
2. **分页参数名统一 `pageNum`（默认 1）/ `pageSize`（默认 5）**，由 PageHelper 在 SQL 层拦截，
   Mapper 里写的是不带 `LIMIT` 的全量查询。
3. **更新语句是全字段覆盖**（不是 selective），所以 `createTime`、`adminCount`、`loginTime`
   这些系统维护字段必须在 Service 里从库里读回来再塞回去，否则会被写空。
4. **`ums_admin.username` 没有唯一索引**，唯一性只在 Service 层用一次查询校验。
5. **Redis 是必需组件**，缺了直接启动失败（这是刻意的，见 02 文档）。
