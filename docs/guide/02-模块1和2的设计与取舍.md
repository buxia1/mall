# 02 · 模块 1 和 2 的设计与取舍

这份文档回答两个问题：**已完成的部分每一处为什么这么写**，以及
**这段时间到底做了哪些有含金量的工作**（哪部分是"填空"，哪部分是真出问题才被迫想清楚的）。

---

## 一、模块 1 · 基础层（对应决策题 D1–D6）

| 决策 | 选择 | 为什么 |
|---|---|---|
| D1 统一返回体 | `CommonResult<T>`：`code` / `message` / `data`，构造器 `protected` + 静态工厂 | 外部只能用 `success/failed/unauthorized/forbidden` 造，签名一冻结，后面所有模块只管用 |
| D2 业务异常继承谁 | `ApiException extends RuntimeException` | 继承 `Exception` 会让每层都写 `throws`，业务代码被污染 |
| D3 异常处理器捕获哪几类 | `ApiException` / `MethodArgumentNotValidException` / `ConstraintViolationException` / `AccessDeniedException` / `Exception` | 前四类给明确语义，最后一个兜底**不让 whitelabel 错误页漏出去** |
| D4 分页怎么封装 | `CommonPage` 同时提供 `restPage(List)`（走 PageHelper `PageInfo`）和 `restPage(Page)`（Spring Data） | 前端只要 `pageNum/pageSize/total/totalPage/list` 五个字段，两种分页实现都适配 |
| D5 Redis 序列化 | key 用 `StringRedisSerializer`，value 用 `GenericJackson2JsonRedisSerializer` | `redis-cli keys '*'` 看到的 key 是**可读的**，不是乱码——这是验收标准之一 |
| D6 日志切面用哪种通知 | `@Around` | 要记录**耗时**和**返回值**，`@Before`/`@After` 拿不到 |

请求日志还做了一层保护：multipart 上传和大体积 body 不记参数，且参数名做了长度限制
（`RequestUtil`），避免把整个文件内容写进日志。

## 二、模块 2 · 认证鉴权与动态 RBAC（对应 D7–D9）

### D7 · token 存哪 —— JWT + Redis 双写

纯 JWT 的问题：签发后无法撤销，登出只能等它自己过期。
纯 Redis 会话的问题：每次请求都要查 Redis，且要自己管 token 生成。

本项目两者结合：

- **JWT** 承载身份（`adminId`、`username`）和到期时间，负责"这串东西没被篡改、没过期"；
- **Redis** 承载"这个会话还活着吗"，负责可撤销。

```java
// AdminTokenService
login()   → jwtTokenUtil.generateToken(adminId, username);
            redisService.set(sessionKey(token), adminId, sessionTtlSeconds);
isActive()→ 验签通过 && Redis 里有这个会话键
logout()  → 验签通过就删 Redis 会话键        ← 登出立刻失效，靠的是这一步
refresh() → isActive 才续 Redis 的 TTL
```

**一个容易被忽略的细节**：Redis key 不是 token 原文，而是 `SHA-256(token)`：

```
mall:security:admin-token:<sha256 十六进制>
```

理由有两条：① 不把可直接使用的凭证写进 Redis（dump、慢查询日志、`keys` 都会泄露）；
② token 很长，做 key 浪费空间。这个取舍值得记住，面试问到"token 存哪"是个加分点。

### D8 · 权限怎么做 —— URL → 资源，数据在库里

没有用 `@PreAuthorize("hasRole(...)")`，因为本项目的权限数据在表里
（`ums_resource.url` 形如 `/admin/**`、`/role/**`），**改了库要立刻生效**，注解写死在代码里做不到。

`DynamicAuthorizationManager` 的逻辑：

1. 没认证或 principal 不是 `AdminIdentity` → 拒绝（上层转成 401）；
2. 取请求路径（`servletPath`，去掉 contextPath）；
3. 取该管理员的资源 URL 集合 → 先读 Redis 缓存，读不到才查库并回填；
4. `AntPathMatcher` 逐个匹配，命中任一放行，全不中拒绝（上层转成 403）。

缓存粒度是 `Map<adminId, Set<url>>` 存在**一个** Redis key 里，所以"清缓存"就是删这一个 key。

> ⚠️ **清缓存是接口契约的一部分**，不是可选优化。
> `02-接口规格.md` 明确写了 `/resource/*` 的增删改必须清权限缓存。
> 因为权限缓存的失效边界就是这个接口——用户在后台加了一条资源并授权，刷新页面就该生效。

### D9 · 过期与续期

- JWT 自己带 `exp`；Redis 会话 TTL 用同一个 `expiration-seconds`。
- `GET /admin/refreshToken` 做的是**滑动续期**：只重置 Redis TTL，**不重新签发 JWT**，所以
  JWT 的 `exp` 到了照样失效（这是安全上的"硬上限"，防止无限续期）。
- 会话 TTL 在构造函数里断言必须 > 0（`AdminTokenService` 构造器），配置错了直接启动失败。

## 三、我做过的工作：哪些是"填空"，哪些是真有含金量

先说结论：**40 多个接口本身大多是普通 CRUD，含金量集中在"让项目第一次真的跑起来"和
"跑起来之后暴露出来的 6 个真实缺陷"**。下面分开讲。

### A. 让项目第一次真的能运行

接手时的状态是：`mvn test` **全绿、63 个测试通过**，但**应用根本启动不了**——
没有 `@SpringBootApplication`、没有任何 `application.yml`、MyBatis 没接进 Spring。
之所以全绿，是因为所有测试要么 mock 掉一切，要么用 standalone MockMvc，**从来没有一个测试
真正启动过 Spring 容器**。这是最值得你记住的一课：

> ⚠️ **"测试全绿"不等于"能跑"。** 真正启动一次，比多写十个单元测试更能发现问题。

我补齐的东西：启动类（`scanBasePackages="com.macro.mall"` + `@MapperScan`）、
`application.yml` + 未跟踪的本地配置模板、`mybatis-spring-boot-starter`、
Redis/Validation starter、可执行 jar 的 `repackage`、8 张表的建表脚本。

### B. 启动之后暴露的 6 个真实缺陷

这 6 个都是**静态检查发现不了、只有真的启动/真的用浏览器点才会暴露**的：

| # | 现象 | 根因 | 修法 | 为什么原来的测试没抓到 |
|:-:|---|---|---|---|
| 1 | 应用起不来 | 全仓库没有 `@SpringBootApplication`、没有配置文件、`mall-mbg` 只依赖裸 `mybatis`，Mapper 不是 Bean | 补启动类 + 配置 + `mybatis-spring-boot-starter` + `@MapperScan` | 没有测试启动过容器 |
| 2 | `jwtTokenUtil` 无法实例化 | `JwtTokenUtil` 有**两个构造器**且都没标 `@Autowired`，Spring 无法选择 | 给单参构造器加 `@Autowired` | 测试里都是 `new JwtTokenUtil(properties)` 手写的 |
| 3 | `AdminTokenService` 找不到 Bean | `@ConditionalOnBean` 写在**被组件扫描的类**上。条件是**扫描阶段**求值的，此时自动配置的 `RedisConnectionFactory` 还没注册，条件恒为 false，Bean 永远不会创建 | 去掉条件装配，Redis 改为必需（**设计变更，已与你确认**） | 测试用手写上下文 + `withBean` 提前注册，绕开了真实时序 |
| 4 | `SecurityConfigTest` 上下文加载失败 | `mall-mbg` 引入 mybatis starter 后 `spring-boot-starter-jdbc` 一起进类路径，`DataSourceAutoConfiguration` 因缺少 JDBC URL 而失败 | 该测试排除 `DataSourceAutoConfiguration`（它本来就把 Mapper mock 掉了） | 之前没有 jdbc 依赖，问题不存在 |
| 5 | 所有带 `@RequestParam` 的接口运行时报 `Name for argument of type [...] not specified` | 本项目只 `import` 了 `spring-boot-dependencies` BOM，**没有继承 `spring-boot-starter-parent`**，而方法参数名要靠 `-parameters` 编译 | 根 pom 设 `maven.compiler.parameters=true` | 之前没有任何不写名字的 `@RequestParam`/`@PathVariable` |
| 6 | 前端登录请求被浏览器拦截，一个请求都发不出去 | 后端**没有任何 CORS 配置**；前端在 `:5173`，直接调 `:8080`，OPTIONS 预检过不去 | `SecurityConfig` 走 `http.cors(...)` + `CorsProperties` 白名单 | 之前的验证都是 curl，**curl 不发预检**，只有真实浏览器才会暴露 |

第 3 条是**设计层面的修改**（`main` 上原来的设计是"Redis 可选"），第 6 条是**只有跑真实前端
才会发现**的。这两条是这次工作里含金量最高的部分。

第 6 条的修法也值得记：走 Spring Security 的 `cors()` 而不是自己加 Filter，
因为前者会把 `CorsFilter` 放在**鉴权之前**，预检直接被应答，不会落到
`DynamicAuthorizationManager` 上被判 403。另外**没有开 `allowCredentials`**——
本项目用 `Authorization` 头传 token，不用 Cookie 会话，开了反而扩大攻击面。

### C. 建立可运行的验收体系

| 产物 | 作用 |
|---|---|
| `AdminAuthenticationIntegrationTest`（8 例） | 跑真实 MySQL+Redis：登录、info、401、403、登出失效、刷新 |
| `AdminRbacCrudIntegrationTest`（5 例） | 分页真的被 PageHelper 拦截、**新建资源授权后不重启即刻可用**、CRUD 走真实 SQL、菜单树、角色分配 |
| `scripts/acceptance/module2-auth.ps1` | 9 项 HTTP 契约验收 |
| `scripts/acceptance/module2-permission-cache.ps1` | 4 步证明权限缓存的"读缓存 / 清缓存后立刻生效" |
| `scripts/acceptance/module2-frontend-e2e.mjs` | 真实 Chrome 驱动 `mall-admin-web`：登录 → 进首页 → 5 个管理页各自取到数据 |

集成测试用 `@Tag("integration")` 标记、**默认被 surefire 排除**，
需要真实 MySQL/Redis 时用 `-Dexcluded.groups=none` 单独跑。这样默认 `mvn test` 在任何机器上都是绿的。

### D. 几个契约与一致性的细节处理

| 处理 | 为什么 |
|---|---|
| `AuthorizationCacheEvictor` 把清缓存注册到**事务提交之后**（`TransactionSynchronization.afterCommit`） | 在提交前清缓存，并发请求会读到未提交的旧数据并把它重新写进缓存，等于白清 |
| `updateRole` 之后重算受影响角色的 `admin_count` | 它是冗余统计字段，`/role/list` 会显示，不重算就是脏数据 |
| 更新语句是全字段覆盖，所以 `createTime`/`loginTime`/`adminCount` 一律从库里读回来再塞回 | 否则前端不传这些字段就会把库里的值写成 `null` |
| `IdListParams` 解析逗号拼接的 ID | 前端用 `join(',')`，**一个都没选时传的是空串**，直接绑 `List<Long>` 会 400 |
| 响应里把 `password` 置空 | 原版会把 bcrypt 哈希返回给前端；前端不读这个字段，置空更安全（请求方向不受影响） |

## 四、如果你要复述，重点复述这四条

1. **为什么 JWT 之外还要 Redis**：JWT 不可撤销，Redis 会话让"登出立刻失效"成为可能；
   key 用 `SHA-256(token)` 是为了不把可用凭证落盘。
2. **动态 RBAC 为什么不用注解**：权限数据在库里，改完要立刻生效，注解写死做不到；
   代价是每个请求要走一次"URL → 资源"匹配，所以加了按 `adminId` 的 Redis 缓存，
   并把"清缓存"作为资源 CRUD 的契约一部分。
3. **401 和 403 为什么必须分开**：前端硬编码判断 401 表示未登录，混了前端行为就错。
4. **"测试全绿但跑不起来"这件事**：真正的验证是启动它、用它，不是看测试条数。
