### Redis

**本项目用的 Redis 是一个 Docker 容器，不是本机安装的 Redis。** 第一步先看它：

```powershell
docker ps
#   ds-redis   redis:7-alpine   0.0.0.0:6379->6379/tcp, [::]:6379->6379/tcp
#   ds-mysql   mysql:8.0        0.0.0.0:3308->3306/tcp, [::]:3308->3306/tcp
```

| 项 | 值 |
|---|---|
| 容器 | `ds-redis`，镜像 `redis:7-alpine`，实际版本 **7.4.11** |
| 启动命令 | `redis-server --appendonly yes --maxmemory 256mb --maxmemory-policy allkeys-lru` |
| 端口 | 同时发布在 `0.0.0.0:6379` 与 `[::]:6379` |
| 密码 | **没有密码**（`CONFIG GET requirepass` 为空；手发 `AUTH 任意值` 会返回 `ERR ... called without any password configured`） |
| 重启策略 | `unless-stopped` —— **只要 Docker Desktop 在跑，它就一直在** |

所以 `spring.data.redis.password` 应当是**空的**（参考项目的 `application-dev.yml` 里也是空的）。

⚠️ **不要在本机再起第二个 Redis 去抢 6379。** 本机确实躺着两个"备用" Redis：

- `D:\develop\redis\redis-server.exe` —— Windows 版 **3.2**，`requirepass 123456`
- WSL Alpine 里的 Redis 7.2.11，`D:\develop\redis\start-redis.bat` 起的就是它（参考项目的遗留路径）

我这次**自己起过 Windows 那个**，它占住 `127.0.0.1:6379`，而容器在 `::1:6379`，
于是脚本里的 `redis-cli -h 127.0.0.1` 和后端（Java 把 `localhost` 解析成 `::1`）连到了**两个不同的 Redis**，
"清缓存立刻生效"那条验收因此**假失败**过一次。这条教训记在坑 4。

补充两点：`ds-mysql`（3308）是**别的项目**的库（`dataagent_meta`），不是 mall，别连错；
Windows 的 `Redis` **服务**指向不存在的 `C:\Program Files\Redis\redis-server.exe`，起不来，直接忽略。

## 二、四个必须知道的坑

### 坑 1 · 本地仓库里有原版 mall 的同坐标产物（会静默用错代码）

`mvn_repo` 里躺着 `com.macro.mall:mall-common:1.0-SNAPSHOT`、`mall-security`、`mall-portal`、
`mall-search`、`mall-agent` 等**原版项目的产物**，坐标和本项目**完全一样**（都是 `com.macro.mall` + `1.0-SNAPSHOT`）。

后果：`mvn -pl mall-admin package`（**不带 `-am`**）会直接从本地仓库拿原版 jar，
打出来的 fat jar 里是**原版的代码**。我实际踩过一次——jar 里的 `logback-spring.xml` 是原版那份 216 行的，
启动直接报 `Missing attribute [condition]`。

**规矩**：动构建就带 `-am`，或者干脆在根目录整仓库构建；
打完 jar 想确认，就检查 `BOOT-INF/lib/mall-common-1.0-SNAPSHOT.jar` 的体积对不对（我们的大约 22KB）。

> 长期建议：给重建项目换个 groupId（比如 `com.rebuild.mall`），从根上避免撞车。

### 坑 2 · 必须开 `-parameters`

本项目只 `import` 了 `spring-boot-dependencies` BOM，**没有继承 `spring-boot-starter-parent`**，
所以 `spring-boot-starter-parent` 默认帮你开的 `-parameters` 是关的。
不开的话，`@RequestParam` / `@PathVariable` 不写名字就运行时报：

```
Name for argument of type [...] not specified, and parameter name information not available via reflection.
```

`pom.xml` 里已经设了 `<maven.compiler.parameters>true</maven.compiler.parameters>`。
⚠️ 改完 pom 后**要 `clean` 一次**——增量编译不会因为属性变了而重新编译。

### 坑 3 · `mvn clean` 会删不掉正在运行的 jar

后端服务跑着的时候，Windows 会锁住 `mall-admin-1.0-SNAPSHOT.jar`，
`mvn clean` 报 `Failed to delete ...`。先停掉服务再 clean。

### 坑 4 · `localhost` 的地址族，会让"同一台 Redis"看起来是两个

后端配的是 `spring.data.redis.host: localhost`，而 **Java 会优先把它解析成 IPv6 `::1`**；
脚本里却习惯写 `redis-cli -h 127.0.0.1`，走的是 IPv4。

Docker 把 6379 同时发布在 `0.0.0.0` 和 `[::]` 上，所以正常情况下两条路到同一个容器，看不出问题。
可**一旦有别的东西占了 `127.0.0.1:6379`**（我起过一个 Windows Redis 正是如此），两条路就分叉：
后端在容器上读写，脚本在另一个实例上删 key。表现是"清了缓存权限却没变"，
看着像缓存失效逻辑有 bug，实际是**验证工具连错了实例**。

**规矩**：`redis-cli` 用 `-h localhost`（和后端同一种解析），或先确认 6379 只有一个监听：

```powershell
Get-NetTCPConnection -State Listen | Where-Object LocalPort -eq 6379 |
  ForEach-Object { $p = Get-Process -Id $_.OwningProcess -ErrorAction SilentlyContinue
                   "$($_.LocalAddress):6379  $($p.ProcessName)" }
```

## 三、从零把这个项目跑起来

```powershell
# 0. 前置：MySQL 3307 起来（见上）；Docker Desktop 在跑，ds-redis 会自动就绪

# 1. 建库（8 张表 + 种子数据）
$mysql = "D:\develop\MySQL\mysql-8.0.34-winx64\bin\mysql.exe"
& $mysql -h 127.0.0.1 -P 3307 -u root -proot -e "CREATE DATABASE IF NOT EXISTS mall DEFAULT CHARACTER SET utf8mb4;"
cmd /c "`"$mysql`" -h 127.0.0.1 -P 3307 -u root -proot mall < sql\auth-schema.sql"
cmd /c "`"$mysql`" -h 127.0.0.1 -P 3307 -u root -proot mall < sql\auth-seed.sql"

# 2. 本地配置（application-dev.yml 已被 .gitignore 忽略，不会提交）
Copy-Item mall-admin\src\main\resources\application-dev.yml.example `
          mall-admin\src\main\resources\application-dev.yml
#   然后按本机情况改：MySQL root/root、Redis 密码留空（容器没设密码）、JWT secret 至少 32 字节

# 3. 构建 + 测试
$env:MAVEN_OPTS = "-Xmx512m -XX:+UseSerialGC"     # 16G 内存机器建议这么配
mvn clean test                                     # 默认排除集成测试
mvn clean test "-Dexcluded.groups=none"            # 含 13 个真实 MySQL/Redis 集成测试

# 4. 起后端
mvn -DskipTests package
java -Xmx512m -XX:+UseSerialGC -jar mall-admin\target\mall-admin-1.0-SNAPSHOT.jar

# 5. 起前端（另开一个窗口）
cd D:\develop\mall-admin-web
npm run dev            # → http://localhost:5173
```

打开 `http://localhost:5173`，用 **`admin` / `macro123`** 登录，应该能进首页、左侧导航出 28 个菜单项。

## 六、故障排查对照表

| 现象 | 大概率原因 |
|---|---|
| 登录返回 `code:500`、message 是 `操作失败`（不是 `Invalid username or password`） | **Redis 连不上**：先看 Docker Desktop 在不在、`ds-redis` 容器起没起（`docker ps`），看后端日志有没有 Redis 连接异常 |
| 清了缓存但权限没变化 | 你的 `redis-cli` 和后端连到了**不同的 Redis**（坑 4）——改用 `-h localhost`，并确认 6379 只有一个监听 |
| 前端报 `blocked by CORS policy` | 后端的 CORS 白名单没覆盖当前前端地址（改 `mall.security.cors.allowed-origin-patterns`） |
| 所有 `@RequestParam` 接口报 `Name for argument ... not specified` | pom 没开 `-parameters`，或者改完没 `clean` |
| 应用起不来，报没有 `RedisService` / `AdminTokenService` Bean | 有人又给这些类加回了 `@ConditionalOnBean`（原因见 [02 文档](02-模块1和2的设计与取舍.md) 缺陷 3） |
| 请求全都 403，但确实登录了 | 该管理员的角色没有被授予对应 URL 的资源权限；去 `/resource/*` 检查，或清掉 `mall:security:authorization:resources` |
| `mvn clean` 报删不掉 jar | 后端还在跑，先停掉 |
| fat jar 启动报奇怪错误、日志配置是原版那份 | 打包时没带 `-am`，混进了本地仓库里的原版产物（坑 1） |
| 默认 `mvn test` 想跳过集成测试 | 它是默认行为；要跑就加 `-Dexcluded.groups=none` |
