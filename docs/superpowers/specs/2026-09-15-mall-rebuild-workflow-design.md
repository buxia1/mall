# Mall 重建协作流程设计

## 目标

在全新的仓库中重建功能等价的精简 mall 系统，并支持两台电脑并行、可追溯地开发。
前端 API 契约和功能验收是外部边界；内部实现重写，避免复制原项目答案代码。

## 工作方式

以模块为最小交付单位，严格依赖顺序实施：基础层、认证鉴权、商品、会员、购物车与订单、营销。
每个模块使用短生命周期功能分支，经过设计、契约确认、实现、自动化验证和 PR 审查后进入 `main`。
同一时间只让一个分支修改同一业务边界，以减少两台电脑间的冲突。

## CRUD 协作

每项 CRUD 先固定实体、表、接口、校验、权限、删除语义和测试范围；用户确认后由智能体协助完成分层实现和验证。
订单、库存、优惠券、权限和秒杀属于业务流程，必须额外定义事务、幂等和并发/补偿策略，不能按普通 CRUD 处理。

## 秒杀边界

秒杀采用 Redis Lua 原子预扣、RabbitMQ 异步削峰、MySQL 条件扣减和订单状态查询。实现必须验证限购、重复消费、消息失败、库存回滚和高并发下不超卖。

## 验收

每个模块先执行对应单元/集成测试与接口契约验证；完成时记录执行命令和结果。全项目最终以后台登录、商品 CRUD、商城浏览加购下单、优惠券与秒杀并发场景作为端到端验收。
