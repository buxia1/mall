# 后台认证与动态 RBAC 设计

## 目标

为 `mall-admin` 提供后台管理员登录、令牌续期/登出、动态 URL 权限与后台角色、菜单、资源管理功能。前台会员的 `/sso/*` 认证不在本阶段实现。

## 架构

`mall-mbg` 仅承载认证所需 7 张表的 MyBatis 模型和 Mapper；`mall-security` 提供 JWT、Redis 会话状态、Spring Security 过滤器与动态授权扩展；`mall-admin` 提供 HTTP 接口与业务服务。

JWT 保存管理员身份和到期信息，Redis 保存可撤销的登录状态并支持滑动续期。受保护请求先认证令牌，再按 URL 获取资源权限；资源权限数据可缓存，`/resource/*` 的创建、更新、删除必须立即清除该缓存。

## 接口与数据边界

- 管理员：`ums_admin`；角色：`ums_role`；菜单：`ums_menu`；资源：`ums_resource`；资源分类：`ums_resource_category`。
- 关联：`ums_admin_role_relation`（管理员-角色）和 `ums_role_menu_relation`（角色-菜单）。
- 登录、刷新、登出、当前信息均使用 `/admin/*`。`/admin/info` 返回 `username`、`menus`、`icon`、`roles`。
- 资源的增删改属于 CRUD，但均附带权限缓存失效；角色关系变更应使相关管理员的授权结果在缓存周期内可见，优先主动失效。
- 未认证统一返回 HTTP 401 与 `CommonResult`；已认证但拒绝访问统一返回 HTTP 403 与 `CommonResult`。

## CRUD 范围

本阶段协助实现管理员、角色、菜单、资源和资源分类的创建、查询、更新、删除，以及管理员分配角色、角色分配菜单/资源的关系维护。每项实现前需报告涉及表、接口、输入校验、权限、缓存失效和测试。

## 非目标

- 不实现 `ums_member`、`ums_member_level`、`/sso/*`、短信验证码或前台 token。
- 不实现商品、订单、营销等业务接口。
- 不依赖重启来使资源权限修改生效。

## 验收

1. 管理员可以登录、刷新 token、登出；登出后令牌不能继续访问受保护接口。
2. `/admin/info` 返回前端所需的账号、头像、角色和菜单结构。
3. 管理员与角色、角色与菜单/资源的分配结果正确。
4. 新增、修改或删除资源后，权限缓存被清除且下一次授权无需重启即可反映变更。
5. 受保护接口对未认证请求返回 401，对无权限请求返回 403，且均为统一 JSON 响应。
